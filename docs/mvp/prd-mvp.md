# prompthub MVP PRD

## 1. 背景

prompthub 是一个提示词管理与分享平台。MVP 阶段聚焦个人和小团队的 PromptOps 工作流：用户可以在一个工作空间内创建、版本化、搜索、复用和评估提示词。


## 2. 目标

- 提供一个集中式提示词仓库。
- 支持带变量和元数据的结构化提示词编写。
- 保留提示词版本历史，使变更可审计、可恢复。
- 让提示词容易查找、复制和复用。

## 3. 非目标

MVP 暂不包含：

- 公开市场、付费体系或创作者变现。
- 评论、讨论区或社交信息流。
- 复杂组织层级或企业级 SSO。
- 实时多人协同编辑。
- 完整的提示词包管理、依赖管理。
- 超出 owner/member 的复杂细粒度权限系统。
- 高级数据分析看板。

## 4. 目标用户

### 主要用户：提示词维护者

创建和迭代提示词的人，可能来自产品、客服、内容、研发或运营团队。

需求：

- 用清晰的上下文和使用说明保存提示词。
- 跟踪提示词的历史变更。
- 复用经过验证的提示词，而不是翻聊天记录。

### 次要用户：团队成员

使用别人创建的提示词的人。

需求：

- 按使用场景搜索提示词。
- 理解变量应该如何填写。
- 快速复制或运行提示词。
- 判断提示词当前是可用、废弃还是实验状态。

## 5. MVP 范围

### 5.1 认证

用户可以：

- 使用邮箱和密码注册。
- 登录和退出登录。
- 查看当前个人资料。

MVP 假设：

- 用户注册后自动进入一个默认工作空间。
- GitHub OAuth 可以后续再加。

### 5.2 工作空间

用户可以：

- 使用默认个人工作空间。
- MVP v1 可以先不开放邀请其他用户，除非团队能力被提前实现。

推荐实现：

- 从第一天保留 `workspaces` 模型。
- 注册时自动创建默认工作空间。
- 可以先建立工作空间成员表，但邀请流程后置。

### 5.3 提示词仓库

用户可以创建、查看、更新、归档和列表查询提示词。

提示词字段：

- 标题
- Slug
- 描述
- 提示词正文
- 消息格式：`single_text` 或 `chat_messages`
- 标签
- 可见性：`private`、`workspace`
- 状态：`draft`、`active`、`deprecated`、`archived`
- 目标模型提供方
- 目标模型名称
- 默认 temperature
- 默认 max tokens
- 使用说明

提示词正文要求：

- 支持使用 `{{variable_name}}` 作为变量占位符。
- 保留换行、缩进和空格格式。
- 对于聊天格式提示词，支持有序消息块，角色包括 `system`、`user`、`assistant`。

### 5.4 提示词变量

用户可以为每个提示词定义变量。

变量字段：

- 名称
- 展示标签
- 描述
- 是否必填
- 默认值
- 示例值

行为：

- 系统可以从 `{{variable_name}}` 占位符中自动推断变量。
- 用户可以在推断后编辑变量元数据。
- 在运行或复制渲染后的提示词前，必填变量必须填写。

### 5.5 版本历史

每次有意义的提示词更新都会创建一个新版本。

版本字段：

- 版本号
- 提示词快照
- 变量快照
- 变更说明
- 作者
- 创建时间

用户可以：

- 查看版本历史。
- 查看某一个版本详情。
- 将历史版本恢复为新的最新版本。

MVP 简化：

- 文本 diff 很有价值，但第一版不强制要求。
- 版本快照建议用 JSON 存储，避免丢失历史结构。

### 5.6 搜索和筛选

用户可以搜索和筛选提示词。

可搜索字段：

- 标题
- 描述
- 标签
- 提示词正文

筛选条件：

- 状态
- 标签
- 目标模型提供方
- 目标模型名称
- 更新时间

MVP 实现：

- MySQL 全文搜索或大小写不敏感的关键词搜索都可以。
- 排序和相关性可以先保持简单。

### 5.7 提示词渲染和复制

用户可以：

- 在预览表单中填写变量。
- 渲染最终提示词。
- 复制渲染后的提示词。

对于聊天格式提示词：

- 按角色分组展示渲染后的消息。
- 提供纯文本复制模式。
- 提供 JSON message array 复制模式。

### 5.8 测试用例

用户可以为提示词创建测试用例。

测试用例字段：

- 名称
- 变量值
- 预期行为说明
- 可选的预期输出

用户可以：

- 新增、编辑、删除和查看测试用例。
- 在配置了模型提供方凭证后，运行某个测试用例。
- 保存运行输出。

MVP 简化：

- 真实模型运行可以通过 feature flag 控制。
- 即使暂时不接入模型执行，测试用例也应先作为结构化示例存在。

### 5.9 运行记录

当模型执行能力开启后，系统保存提示词运行记录。

运行记录字段：

- Prompt ID
- Prompt Version ID
- Test Case ID，可选
- 提供方
- 模型
- 输入变量
- 渲染后的提示词快照
- 输出文本
- 延迟
- Token 使用量，如提供方返回
- 错误信息，如运行失败
- 创建人
- 创建时间

用户可以：

- 查看某个提示词的最近运行记录。
- 手动对比不同运行输出。

### 5.10 API Key 和模型提供方

MVP 支持：

- OpenAI-compatible API 配置。

用户可以：

- 保存一个工作空间级别的模型提供方配置。
- 在提示词上选择提供方和模型。

安全要求：

- API Key 不能通过任何 API 响应返回。
- API Key 必须加密存储，或使用安全的 secret 管理机制存储。
- 日志中不能出现原始 API Key。

## 6. 用户故事

### 创建提示词

作为提示词维护者，我希望创建包含标题、描述、标签、变量和模型设置的提示词，以便后续复用。

验收标准：

- 用户可以将新提示词保存为草稿。
- 用户可以将提示词标记为可用状态。
- 用户可以看到系统从占位符中推断出的变量。
- 保存前能提示无效变量语法。

### 搜索提示词

作为团队成员，我希望通过关键词和标签搜索提示词，以便快速找到合适的提示词。

验收标准：

- 搜索返回当前工作空间内匹配的提示词。
- 归档提示词默认隐藏。
- 筛选条件可以和关键词搜索组合使用。

### 提示词版本管理

作为提示词维护者，我希望提示词编辑后自动产生版本，以便审计和恢复历史内容。

验收标准：

- 更新提示词内容会创建新版本。
- 用户可以查看历史版本。
- 用户可以恢复历史版本。
- 版本历史展示作者、时间和变更说明。

## 8. 数据模型

推荐初始数据表：

- `users`
- `workspaces`
- `workspace_members`
- `prompts`
- `prompt_versions`
- `prompt_variables`
- `prompt_test_cases`
- `prompt_runs`
- `tags`
- `prompt_tags`
- `provider_configs`

### 核心实体说明

`prompts`

- 保存当前提示词元数据和当前可编辑状态。
- 包含 `current_version_id`。
- 属于一个工作空间。

`prompt_versions`

- 保存不可变快照。
- 快照应包含正文、消息块、变量、模型设置、状态和标签。

`prompt_variables`

- 保存当前变量元数据。
- 历史变量状态由版本快照保存。

`prompt_runs`

- 保存针对某个具体提示词版本的执行记录。
- 不应依赖可变的当前提示词状态。

## 10. 权限规则

MVP 规则：

- 用户可以访问自己工作空间内的提示词。
- 提示词创建者和工作空间 owner 可以更新或归档提示词。
- 工作空间成员可以查看和运行工作空间可见的提示词。
- 私有提示词只对创建者可见。

实现说明：

- 即使第一版每个工作空间只有一个用户，也要在每个查询中强制工作空间隔离。

## 11. UX 要求

- 提示词编辑器必须保留格式。
- 如果实现成本可控，变量占位符应有视觉高亮。
- 提示词列表应优先适合快速扫描，而不是做成营销展示页。
- 空状态应提供直接操作，例如“创建提示词”。
- 归档、恢复等有影响的操作应有确认。
- 复制操作应有即时成功反馈。
- 测试运行失败时应展示提供方、模型和错误上下文，但不能暴露密钥。

## 12. 成功指标

MVP 可以用以下标准衡量：

- 用户可以在不依赖外部笔记的情况下创建并复用至少 20 个提示词。
- 小型工作空间内搜索能在 300 ms 内返回有用结果。
- 一个提示词可以完整完成编辑、版本化、恢复、渲染和复制流程。
- 至少一个提示词可以拥有多个测试用例和保存的运行记录。
- 没有任何 API 响应暴露模型提供方密钥。

## 14. 待确认问题

- MVP 是否只支持个人工作空间，还是立即支持邀请式团队成员？
- 前端技术栈使用 Next.js 还是 Vite React？
- 第一个模型提供方是只支持 OpenAI，还是支持通用 OpenAI-compatible？
- 提示词版本是在每次保存时创建，还是只有用户填写变更说明时创建？
- 公开分享是否作为 v1.1 的只读链接能力，还是等内部团队流程稳定后再做？

## 15. 推荐 MVP 默认决策

- 使用 Go + Gin 后端和 MySQL。
- 除非需要服务端渲染，否则使用 Vite React 构建前端应用。
- 使用 REST API。
- 使用 OpenAI-compatible 提供方配置。
- 当提示词内容、变量、标签或模型设置发生变化时创建新版本。
- 在版本管理和测试能力稳定前，暂缓公开分享功能。
